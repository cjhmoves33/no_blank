# 링 시점

카메라는 링 안에서 도형을 바라보며, 사용자가 배경을 끌면 도형 둘레를 돌고 휠을 굴리면 다가가거나 물러납니다. 높이와 거리에는 한계가 있어서 카메라는 로프 밖으로 나가지 않습니다.

## Sub-features

- `ring-home`: 처음 카메라 위치에서 링, 로프, 샌드백, 벽시계, 창으로 든 햇빛이 보입니다.
- `ring-orbit`: 배경을 좌우로 끌면 카메라가 도형 둘레를 돕니다.
- `ring-polar-limit`: 위아래로 크게 끌어도 카메라는 가장 높은 곳과 가장 낮은 곳에서 멈춥니다.
- `ring-distance-limit`: 휠을 많이 굴려도 카메라는 가장 가까운 거리와 가장 먼 거리에서 멈춥니다.

## How to get to it (user POV)

- 페이지를 열면 처음 카메라 위치에서 시작합니다.
- 도형이 아닌 곳(배경)을 누른 채 끌면 카메라가 돕니다.
- 마우스 휠을 굴리면 거리가 바뀝니다.

## Driving it with verify.mjs

Preconditions:

- 증명할 빌드가 준비되어 있고 `doctor` 가 통과합니다.

- **처음 위치.** 페이지를 엽니다. `node $V shoot <이름> --views home` 을 실행합니다. `home.png` 에 도형이 화면 가운데에 있고, 뒤로 로프와 벽시계가 보입니다.
- **좌우 회전.** 배경을 좌우로 끕니다. `--views turned-left,turned-right` 로 찍습니다. 두 장 모두 `home` 과 다른 방향에서 본 링이고, 도형은 여전히 가운데에 있습니다.
- **높이 한계.** 배경을 위아래로 크게 끕니다. `--views high,low` 로 찍습니다. `high` 는 위에서 내려다본 매트, `low` 는 천장 보가 보이는 낮은 위치이고, 두 장 모두 로프 안쪽에서 본 모습입니다.
- **거리 한계.** 휠을 많이 굴립니다. `--views near,far` 로 찍습니다. `near` 는 도형이 크게, `far` 는 `home` 과 비슷한 크기로 보입니다. 로프가 카메라를 가로질러 화면을 덮으면 실패입니다.
- **전후 비교.** 장면을 바꾼 변경은 `node $V run --before <ref> --after <ref | WORKTREE>` 로 기본 시점 7개를 비교합니다. 바뀌면 안 되는 변경은 모든 시점이 0 개여야 하고, 바뀌어야 하는 변경은 `diff/` 의 빨간 영역이 바뀐 물체에만 있어야 합니다.

## Gotchas

- 드래그는 화면 왼쪽 가장자리(가로 12%)에서 시작합니다. 그 자리에 누를 수 있는 소품이 생기면 드래그가 소품에 먹혀 카메라가 돌지 않습니다. 이때는 `VIEWS` 의 시작점을 다른 배경으로 옮깁니다.
- 회전 각도는 끈 픽셀 수를 화면 높이로 나눈 값으로 정해지므로, 시점 크기(1280×800)를 바꾸면 이전 증거와 비교할 수 없습니다.
- `far` 는 처음 위치와 거리가 거의 같아서 `home` 과 비슷하게 보입니다. 거리 한계가 바뀌는 변경에서만 차이가 납니다.
- 동작 줄이기를 끄면(`--motion`) 카메라 관성이 켜져 같은 입력이 다른 프레임을 만듭니다. 전후 비교에는 쓰지 않습니다.
