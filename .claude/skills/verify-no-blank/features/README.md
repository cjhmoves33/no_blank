# no_blank 검증 지도

이 폴더는 체육관 장면에서 사용자가 만나는 동작을 검증하는 기준입니다. 앱을 조작하기 전에 이 색인을 읽고, 맞는 기능 파일을 절차로 씁니다. 용어는 [`docs/GLOSSARY.md`](../../../../docs/GLOSSARY.md)를 따릅니다.

## 기본 전제

- 저장소 루트에서 `V=.claude/skills/verify-no-blank/scripts/verify.mjs` 로 둡니다.
- 증명할 상태를 `node $V prepare <이름> <ref | WORKTREE>` 로 빌드합니다.
- `node $V doctor` 의 `ok` 줄이 모두 통과해야 합니다.
- 이 검증이 띄운 인스턴스(포트 3101, 3102)만 조작합니다. 3000 번은 사용자의 dev 서버입니다.

## 조작 규칙

- 모든 절차는 새로 연 페이지에서 시작합니다. `shoot` 은 시점마다 페이지를 다시 엽니다.
- 입력은 시점 이름으로 고릅니다. 좌표와 입력 내용은 `scripts/verify.mjs` 의 `VIEWS` 가 정본입니다.
- 기본은 대부분의 사용자와 같은 '동작 켬'입니다. 동작 줄이기를 켠 사용자의 화면을 볼 때만 `--reduced-motion` 을 씁니다.
- 0.1초 안에 끝나는 타격 반응은 정지 화면이 아니라 클립(`*-clip` 시점)의 프레임으로 확인합니다. 페이지의 시계를 스크립트가 쥐므로 클립도 같은 입력이면 프레임마다 같습니다.

## 증명과 건너뜀 보고

- 입력과 그 결과를 함께 남깁니다. 시점 JSON 의 `actions` 가 입력이고, PNG 가 결과입니다.
- 화면에 보이지 않는 결과(효과음, 커서)는 JSON 의 `audioPeak`, `cursor` 로 보고합니다. `compare` 와 `run` 의 비교표에도 나옵니다.
- 보고에는 빌드 커밋, 시점 이름, 증거 경로를 적습니다.
- 닿을 수 없는 절차는 시도한 명령과 채워지지 않은 전제를 적어 실패로 보고합니다. 다른 경로로 대신 확인한 것을 그 절차의 통과로 적지 않습니다.

## 기능 파일 형식

각 파일은 H1 제목과 사용자에게 보이는 동작을 설명하는 한 문단으로 시작하고, 이어서 H2 네 개를 이 순서로 둡니다.

1. `Sub-features`: 짧은 ID 와 한 줄 설명
2. `How to get to it (user POV)`: 사용자가 그 동작에 닿는 모든 길
3. `Driving it with verify.mjs`: `Preconditions:` 로 시작하고, 사용자 동작과 정확한 명령, 관찰할 결과를 짝지은 목록
4. `Gotchas`: 검증을 헛되게 하거나 무효로 만드는 함정

## 기능

- [링 시점](./ring-view.md): 오른쪽 버튼 드래그로 도는 카메라, 높이와 거리의 한계
- [레킹볼 타격](./strike.md): 잽과 휘두르기, 맞는 순간의 효과음과 흔들림·비틀림, 왼쪽 드래그, 커서
- [동작 줄이기](./reduced-motion.md): 먼지와 카메라 관성이 멈추고, 친 레킹볼이 곧 가라앉는지
- [WebGL 대체 화면](./webgl-fallback.md): WebGL 을 쓸 수 없을 때의 화면
